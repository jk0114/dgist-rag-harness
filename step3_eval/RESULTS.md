# 검색(Retrieval) 평가 결과

`python -m step3_eval.run_eval`로 얻은 최신 결과 요약. 원본 데이터는 [`data/queries.json`](data/queries.json)(질의+정답),
[`data/hyde_cache.json`](data/hyde_cache.json)(HyDE 가상 문서), [`data/results/latest.json`](data/results/latest.json)(질의별 상세 결과)에 있다.

## 평가 방법

- **질의**: DGIST 연구실 232개 각각에 대해 `"{연구 분야}에 관심이 있는데 어떤 과목을 들으면 좋을까?"` 형태로 자동 생성.
- **정답(GT)**: 그 연구실이 실제로 추천하는 과목 목록(`extract_course_tree.py`가 학교 페이지에서 추출).
- **비교 대상**: `vanilla`(순정 dense 검색) / `vanilla+hyde` / `graph-rag`(키워드 그래프 재점수화) / `graph-rag+hyde`.
- **지표**: Precision@10·Recall@10·MRR·nDCG@10(모두 top-10 고정), MAP(전체 랭킹, K 무관). 이 데이터셋은 질의별 정답 개수 편차가 크므로(3~33개), **nDCG·MAP이 질의 간 비교에 가장 공정한 지표**다. 계산식은 [`run_eval.py`](run_eval.py)의 `metrics()`/`average_precision()`이 정의다.
- **검색 풀**: 청크 60개를 먼저 뽑은 뒤 과목 단위로 중복 제거해서 과목 랭킹으로 바꾸고, 그 상위 10개 과목으로 Precision/Recall/nDCG를 계산한다.

## 청크 → 과목 변환(dedup)과 "미발견"의 기준

한 과목의 강의계획서는 보통 여러 페이지(여러 청크)로 나뉘어 색인돼 있는데, GT(정답)는 청크 단위가 아니라 **과목 단위**로 정의돼 있다("이 연구실은 A과목, B과목을 추천한다"). 그래서 평가·케이스 스터디 스크립트는 청크 랭킹을 과목 랭킹으로 바꾸는 dedup을 한 번 거친다 — [`run_eval.py`](run_eval.py)와 [`case_study.py`](case_study.py)가 공유하는 `hits_to_courses()`([run_eval.py:79-94](run_eval.py#L79-L94)):

```python
def hits_to_courses(hits, score_key):
    ordered = sorted(hits, key=lambda h: h[score_key], reverse=True)  # 점수 내림차순 정렬
    seen, out = set(), []
    for h in ordered:
        name = strip_paren(SOURCE_RE.match(h["source"]).group("name"))  # 파일명에서 과목명 추출
        if name in seen:
            continue     # 이 과목은 이미 (더 높은 점수의 청크로) 리스트에 들어감 — 이 청크는 버림
        seen.add(name)
        out.append(name)
    return out
```

동작 방식: 후보 풀의 모든 청크를 점수 내림차순으로 정렬한 뒤 위에서부터 훑으면서, **과목명이 처음 나오는 시점의 점수(=그 과목이 가진 청크들 중 가장 높은 점수)를 그 과목의 대표 점수로 삼고, 같은 과목의 나머지 청크는 버린다.** 즉 "과목의 순위" = "그 과목에 속한 청크 중 가장 잘 맞은 한 조각의 순위"다(청크 점수를 평균 내거나 합산하지 않음 — max-pooling에 가깝다).

**후보 풀 크기(파이프라인/스크립트별로 다름):**

| | vanilla / vanilla+hyde | graph-rag / graph-rag+hyde |
|---|---|---|
| `run_eval.py` | `retrieve(text, 60)` — 청크 60개 | `graph_rescore()` = dense 30개 + 그래프 이웃 전부(제한 없음, 보통 100개 이상) |
| `case_study.py` | `retrieve(text, 100)` — 청크 100개 | 위와 동일 |

**"미발견"의 정확한 뜻**: 이 청크 풀(전체 코퍼스 1905개 청크 중 위 크기만큼 뽑은 것) 안에 그 과목에 속한 청크가 **단 하나도** 없었다는 뜻이다. "과목 랭킹에서 순위가 낮다"가 아니라 "애초에 후보에도 못 들었다"는 더 강한 실패 신호 — 그래서 case_study.py의 순위표에서 숫자(예: 41위) 대신 "미발견"이 뜨는 항목은, 61위나 101위 같은 "약간 아쉬운" 위치가 아니라 그 과목의 어떤 페이지도 상위 후보 근처에도 못 갔다는 뜻이다.

**이 dedup은 평가·분석 스크립트(`run_eval.py`, `case_study.py`)에만 있고, 실제 챗봇(`app.py`)이나 실험실 페이지(`pages/1_그래프_실험실.py`)에는 없다.** 그쪽은 청크를 과목 단위로 합치지 않고 각각 독립된 항목으로 그대로 LLM 프롬프트/화면에 넘긴다 — 같은 과목의 청크 2개가 둘 다 top-k에 뽑히면 둘 다 `[근거]`에 별도 번호로 들어간다([pipelines.py:51-53](../step2_retrieval/pipelines.py#L51-L53)의 `_ctx()` 참고). dedup은 순전히 "청크 단위 검색 결과를 과목 단위 GT와 비교하기 위한" 채점상의 편의이지, 실제 검색·생성 파이프라인의 동작이 아니다.

## 지표 설명

`retrieved`는 한 질의에 대해 모델이 뽑은 과목 랭킹(점수 내림차순), `relevant`는 GT 정답 과목 집합, `k=10`이다.
아래 다섯 지표 모두 [`run_eval.py`](run_eval.py)의 `metrics()`/`average_precision()`이 정의 그대로다.

### Precision@k — "상위 k개 중 몇 개가 정답인가"
```
precision = (상위 k개 중 정답 개수) / k
```
가장 직관적인 지표. 다만 이 데이터셋처럼 질의마다 정답 개수가 3~33개로 편차가 크면, 정답이 5개뿐인 질의는 Precision@10이 구조적으로 0.5를 못 넘어서 질의 간 비교가 불공정해진다.

### Recall@k — "전체 정답 중 몇 개를 상위 k개 안에서 찾았나"
```
recall = (상위 k개 중 정답 개수) / (전체 정답 개수)
```
Precision과 분모만 다르다(자른 개수 k 대신 전체 정답 개수). 정답이 30개인 질의는 상위 10개만 봐서는 Recall@10이 구조적으로 0.33을 못 넘는다 — Precision과 마찬가지로 질의별 정답 개수 편차에 취약하다.

### MRR (Mean Reciprocal Rank) — "정답을 얼마나 빨리 찾았나"
```
그 질의의 RR = 1 / (첫 번째로 나온 정답의 순위)   # 정답을 하나도 못 찾으면 0
MRR = 모든 질의의 RR 평균
```
상위 랭킹 중 **가장 먼저 등장한 정답 하나**의 위치만 본다. 예를 들어 1위가 정답이면 RR=1.0, 3위에서야 처음 정답이 나오면 RR=1/3. "사용자가 리스트를 위에서부터 몇 번째까지 봐야 쓸모있는 답을 만나는가"에 가까운 지표라, top-1 적중률과 강하게 연동된다(이 프로젝트에서 HyDE가 MRR을 깎아먹는 것도 top-1 적중률 하락이 직접 원인이었다).

### nDCG@k (normalized Discounted Cumulative Gain) — "정답이 상위에 몰려 있을수록 높은 점수"
```
DCG  = Σ (i번째가 정답이면 1, 아니면 0) / log2(i + 1)     # i = 1..k
IDCG = Σ 1 / log2(i + 1)                                  # i = 1..min(정답 개수, k) — 이론상 최댓값
nDCG = DCG / IDCG
```
정답이 몇 위에 있는지에 따라 `log2(순위+1)`로 점수를 깎는다(1위 정답과 10위 정답은 기여도가 다르다). **`IDCG`를 `min(정답 개수, k)`로 정규화**하는 게 핵심 — 이 덕분에 정답이 3개뿐인 질의든 30개인 질의든 이론적 최댓값이 항상 1.0이 되어서, Precision/Recall@k와 달리 **질의별 정답 개수 편차에서 자유롭다**.

### MAP (Mean Average Precision) — "랭킹 전체를 보고, 정답을 찾을 때마다의 정밀도를 평균"
```
그 질의의 AP = Σ (i번째가 정답이면, 그 순간까지의 precision) / (전체 정답 개수)   # i는 자르지 않은 전체 랭킹
MAP = 모든 질의의 AP 평균
```
k로 자르지 않고 랭킹 전체를 본다. 정답을 하나 찾을 때마다 "지금까지 본 것 중 정답 비율"을 기록해서 정답 개수로 나누기 때문에, 끝까지 못 찾은 정답은 자동으로 0점 취급되면서도 **정답 개수가 몇 개든 같은 잣대**로 비교된다.

nDCG@k와 MAP은 둘 다 질의별 정답 개수 편차 문제에서 자유로워서, 이 프로젝트에서는 이 둘을 **가장 신뢰할 수 있는 비교 지표**로 삼았다. Precision/Recall@k는 참고용으로만 본다.

## 관찰

**graph-rag가 전반적으로 가장 우수하다.** nDCG@k(0.318)와 MRR(0.571) 모두 4개 파이프라인 중 최고 — 코퍼스 안의 실제 키워드/구조 연결을 근거로 이웃 청크 점수를 끌어올리는 방식이 vanilla 대비 확실한 개선을 보인다.

**HyDE는 MRR을 오히려 낮춘다** (vanilla: 0.52→0.48, graph-rag: 0.57→0.49). 원인을 질의 단위로 추적해보면: HyDE가 질의 키워드에 정확히 맞춰 **아주 좁고 구체적인 가상 과목 하나**를 지어내는데(예: "유기금속촉매론"), 이게 임베딩을 그 특화 주제 쪽으로 확 당겨버려서, 정작 GT에 포함된 더 넓은 커리큘럼(기초 화학 과목 등)을 밀어낸다. 예:

> 질의: "유기화학, 유기금속화학, 촉매에 관심이 있는데..."
> - vanilla top-1: 유기화학Ⅰ (정답 ✓)
> - vanilla+hyde top-1: 유기금속화학 (정답 아님 ✗)
> - HyDE가 지어낸 문서: *"유기금속촉매론 ... organometallic catalysis, transition metal complexes..."*

MAP은 vanilla+hyde(0.168)가 vanilla(0.160)보다 소폭 높아서, "전체 랭킹 어딘가에는 정답이 더 들어있다"는 점에서 완전히 손해는 아니다 — 다만 1등을 맞추는 능력(MRR)은 떨어진다.

### 시도했다가 되돌린 것: HyDE 프롬프트를 "더 넓게" 쓰게 하기

가설: "가상 문서를 기초~응용을 아우르는 넓은 내용으로 쓰게 하면 HyDE의 좁은-특화 편향이 완화되지 않을까?" → **실제로는 vanilla+hyde의 5개 지표가 전부 더 나빠졌다** (MRR 0.482→0.471, nDCG 0.270→0.262, MAP 0.168→0.164).

이유로 추정되는 것: 코퍼스 안의 실제 문서(강의계획서)는 전부 "구체적인 과목 하나" 형태다. 가상 문서를 일부러 뭉뚱그려서 넓게 쓰면, 그 문서와 코퍼스 안의 특정 문서들(정답 포함) 사이의 유사도가 전반적으로 흐려진다 — 즉 "기초 과목도 챙기게 하려는" 의도가 "모든 과목과 애매하게 비슷한 흐릿한 벡터"를 만드는 부작용으로 이어졌다. 부수적으로 생성 언어도 한국어 비중이 82%→100%로 바뀌었는데(실제 강의계획서 교과개요는 영어인 경우도 많음), 이 역시 코퍼스 문체와의 괴리를 키웠을 수 있다. 이 프롬프트 변경은 되돌렸고, [`hyde.py`](../step2_retrieval/hyde.py)는 "행정 필드 제거" 버전만 유지한다.

**시사점**: 좁은 특화 과목과 넓은 기초 과목을 동시에 잘 맞추려면, 가상 문서 하나로는 구조적 한계가 있어 보인다 — 다음 시도로는 가상 문서를 여러 개(특화용 + 기초용) 만들어 검색 결과를 합치는 방식이 유력한 후보다.

## 케이스 스터디: 특정 관심분야로 직접 질의해서 확인

macro-average 숫자만으로는 "구체적으로 어떤 과목이 살아나고 어떤 과목이 사라지는지"가 안 보여서, 관심분야 4개를 직접 질의로 넣고 목표 과목들의 **전체 랭킹(과목 100개 풀) 중 순위**를 비교했다. 케이스마다 HyDE가 실제로 지어낸 가상 강의계획서 원문과, graph-rag+hyde가 그 과목을 후보로 뽑을 때 **키워드 그래프로 어떤 다른 과목들과 연결돼 있었는지**(`step2_retrieval/graph_rag.py`의 `Graph.keywords`/`kw_index` — [build_keyword_cache.py](../step2_retrieval/build_keyword_cache.py)가 LLM으로 뽑아둔 청크별 키워드를 공유하는 청크끼리 잇는 그 그래프)도 같이 적는다. ### 네 케이스를 종합한 패턴

1. **질의 키워드와 과목명이 이미 거의 일치하면**(양자컴퓨팅) 4개 파이프라인 다 잘 맞아서 차이가 없다 — HyDE/graph-rag가 힘을 발휘할 여지가 없는 "쉬운" 케이스.
2. **암묵적으로 필요한 기초 과목**(LLM→기계학습/강화학습/딥러닝, 로보틱스→동역학, 단백질 디자인→기계학습/강화학습)은 vanilla가 잘 놓치는데, HyDE(특히 graph-rag+hyde)가 확실히 되살린다 — 동역학이 41위→4위, 단백질 디자인 케이스의 기계학습개론이 41위→4위로 뛴 게 대표적. **의도했던 recovery 효과가 실제로, 그것도 반복적으로 작동한다.**
3. 다만 공짜가 아니다 — **`컴퓨터 비전 개론`은 LLM·로보틱스·단백질 디자인 세 케이스 모두에서 vanilla가 이미 top-10으로 잘 잡고 있었는데, HyDE 계열에서는 매번 밀려난다**(9→미발견, 10→39, 10→53). 세 번 연속 같은 방향으로 나온 걸 보면 우연이 아니라 상당히 신뢰할 수 있는 규칙성이다: HyDE가 생성하는 문서는 특정 기술 서사 하나(NLP, 로봇공학, 단백질 구조예측 등)에 집중하는데, "비전"은 그 서사에 자연스럽게 안 끼는 경우가 많아 계속 밀려난다.
4. graph-rag 단독(HyDE 없이)이 가끔 다른 걸 잡아내기도 한다(양자컴퓨팅에서 선형대수학을 26위로 찾은 건 graph-rag뿐, graph-rag+hyde는 못 찾음) — HyDE 텍스트가 임베딩 방향을 너무 강하게 한쪽으로 좁혀버리면, graph-rag의 구조/키워드 이웃 탐색을 오히려 방해할 수 있다.
5. **생물학·수학처럼 질의 표현과 어휘 자체가 먼 기초과목(선형대수학, 면역학 등)은 4개 파이프라인 다 거의 못 찾는다.** HyDE도 결국 LLM이 그 관심분야에 대해 "떠올리는" 내용에 한정되므로, 애초에 HyDE가 생성한 가상 문서 자체에 그 기초과목의 언어가 안 나오면 recovery가 안 된다 — HyDE는 "질의에 없는 당연한 연관어"까지 만들어주는 만능 해결책은 아니다.

### 왜 graph-rag가 "미발견"이 더 많아 보여도 불리한 게 아닌가

graph-rag의 dense 시드는 30개(`POOL_K=30`, vanilla의 100개보다 적음)라서 얼핏 후보 풀이 더 좁아 불리해 보일 수 있는데, 실제로는 그 반대다 — [graph_rag.py:126-136](../step2_retrieval/graph_rag.py#L126-L136)이 그 30개의 그래프 이웃(구조적 인접 + 키워드 공유)을 개수 제한 없이 전부 풀에 추가하기 때문에, 최종 후보 풀은 항상 vanilla보다 크다:

| 질의 | vanilla (청크→과목) | graph-rag (청크→과목) |
|---|---|---|
| LLM | 100→57개 | 165→65개 |
| 로보틱스 | 100→57개 | 185→80개 |
| 양자컴퓨팅 | 100→54개 | 149→60개 |
| AI 단백질 디자인 | 100→54개 | 198→84개 |

그러니 graph-rag에서 뜬 "미발견"은 후보가 부족해서가 아니라, **vanilla보다 넓은 그물을 쳤는데도 안 걸렸다**는 뜻 — 오히려 "이 과목은 이 질의와 진짜 안 엮여 있다"는 더 신뢰할 수 있는 신호에 가깝다.

**결론**: recovery는 분명히 일어나지만 다른 과목을 밀어내는 대가가 따르는 트레이드오프이고, 그 방향은 "HyDE가 다루지 않은 인접 분야는 밀려난다"는 꽤 예측 가능한 패턴을 보인다. macro-average 지표(HyDE가 MRR은 깎고 MAP은 살짝 올리는 패턴)와도 일관된 그림이다.
